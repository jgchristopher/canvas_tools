What is wrong, and what would fix it

The problem this contract exists to close, and the outcomes that would mean it closed.

John walks people through Obsidian canvases (for example Shepherd Factory Lifecycle) by panning and zooming by hand. Mostly this happens over screen-share in meetings, sometimes on a projector, and possibly on an unattended display that should cycle on its own.

Hand navigation is slow, inconsistent between runs, and pulls attention away from the talk. There is no way to save a sequence of viewpoints, step through them with a keyboard or presentation clicker, or let the canvas cycle unattended.

Goals

×5
  1. Present a deck of 5+ slides on Shepherd Factory Lifecycle start to finish using only keyboard or clicker, with zero mouse panning or zooming.
  2. Auto-play a deck unattended: it loops with each slide's own duration (10s default) for 10+ minutes without manual input.
  3. The same deck, after Obsidian Sync, plays on John's phone using only the on-screen tap bar.
  4. A presentation session that does not edit slides leaves the .canvas file byte-identical.
  5. A slide can carry one saved highlight path: presenting that slide shows the path highlighted, and moving to a slide without a path shows no highlight.

What actually happens when you run it

Every build phase goes through the same five stages. These are the real agents and the real gates — the points where the run can stop before anything is committed. Human gates in the plan above are not build phases: nothing is specced, built, or committed for them.

per build phase
Scout ideation:scout Reads the codebase against the spec and scores five evidence gates before a line is written. GOHOLD Stops here when: Under --strict a HOLD stops here — nothing is built.
Build general-purpose Implements the spec, then runs the validation the spec itself declares. BUILTNO-OPFAIL Stops here when: Failed validation stops here. An empty diff is a NO-OP and also stops here — review never runs.
Review ideation:reviewer Reads the diff back against the spec and returns findings counted by severity. PASSFAIL Stops here when: An unavailable reviewer stops here under --strict; otherwise it commits as validation-only.
Fix general-purpose Applies or refutes every blocking finding, then hands back for another review. FIXEDFAIL Stops here when: Still FAIL on cycle 3 stops here — changes are left unstaged, not committed.
Commit general-purpose Stages only the files the builder named and writes the spec path into the commit body. COMMITTEDFAILED Stops here when: If neither the builder nor the phase named a file, it refuses to commit blind rather than git add -A.
review → fix → review · 3 cycles max, then it stops

Waves, not a queue

Phases are grouped into 4 waves from their declared prerequisites. A wave dispatches together; the next one waits for all of it. No phase here declares files, but autopilot derives them from each spec’s File Changes tables before dispatch, so colliding phases can still be serialised. A phase whose spec has no readable File Changes section is treated as parallel-safe, and the engine logs a warning saying so.

Failure strands, it does not retry

A failed phase is not retried, and everything downstream of it is marked SKIPPED rather than attempted. Here that means Slide model, viewport fit, internals failing costs 3 more phases, and Slides menu failing costs 2 more phases.

Resume is a git question

Re-running skips any phase whose spec path already appears in a commit body — which is why the commit stage writes it there. 3 build phases are expected to leave one; the 1 human gate commits nothing.

Non-strict: it degrades loudly

If the scout holds or the reviewer is unavailable, the phase proceeds and says so in its warnings rather than failing. The result reports validation-only, never a bare pass.

What was considered and turned down

A rejected alternative is evidence, not an oversight. Before proposing one of these, read why it lost.

×15

  • A slide is a captured canvas rect from the current view

    Instead of A slide points at a group or node and zooms to fit it. Matches 'view points' literally and needs no groups per framing

  • A slide can optionally show one highlight path

    Instead of Views only. Lets John walk routes like 'Workable - Merged' as slides, reusing PR #1

  • Auto-play is in the MVP

    Instead of Full tier after manual presenting. John wants unattended use available from the first version

  • Built-in presentation keys plus bindable Next/Previous commands

    Instead of Commands only, or built-in keys only. Clickers work out of the box and keys stay customizable

  • Presentation mode hides canvas UI only

    Instead of True browser full-screen. Fewer edge cases (Esc, popouts, mobile); Obsidian's full-screen covers projector use

  • Per-slide durations with a default

    Instead of One interval per deck. John wants per-slide control for kiosk loops

  • On-screen tap bar for touch navigation

    Instead of Swipe gestures. No conflict with canvas pan and pinch

  • Reorder with Move up/down in the menu

    Instead of Drag-to-reorder panel. Plain tap actions, far less UI

  • Exit clears all path highlights

    Instead of Restore the path showing before the presentation. John's choice

  • Custom viewport fit (set tx/ty/tZoom) instead of zoomToBbox

    Instead of Obsidian's zoomToBbox. zoomToBbox caps zoom at 100% and adds 10% padding, so zoomed-in captures would not replay as framed

  • Phase 1 starts with a viewport spike and is rated medium risk

    Instead of Treat viewport internals as known, low risk. Hidden-dependency critic: the spike doc has no viewport section

  • Slides and paths share one per-view Highlighter via a path-controller API

    Instead of A separate slide highlighter. Hidden-dependency critic: two highlighters would overwrite each other's ct-path-* classes and the 300ms data poll

  • Presentation captures keys before the canvas and blocks node select/drag/nudge

    Instead of Plain key listeners alongside canvas handling. Hidden-dependency critic: Space pans and arrows nudge nodes, and a nudge or selection saves the file, breaking Goal 4

  • Auto-play and key map are pure modules with fake-timer tests; a no-write test guards Goal 4

    Instead of Only judgment checks for auto-play and no-write. Success-criteria critic: both are mechanical properties a command can check

  • Per-slide paths stay in MVP with their own goal (Goal 5)

    Instead of Move per-slide paths to a later tier. Scope-creep critic flagged MVP work with no goal; John chose the feature, so a goal was added instead
