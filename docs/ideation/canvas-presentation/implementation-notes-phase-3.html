Implementation Notes — Phase 3

Canvas Presentation · 2026-10-25 · Presentation mode and auto-play

Key capture — Scope plus window capture

Context
The spec left the capture point to the spike: a window-capture listener or an Obsidian Scope. The spike found that Obsidian's keymap listens at window capture from startup, so it always runs first.
Decision
Both. A pushed catch-all Scope performs the action and returns false. A window-capture listener only calls stopPropagation on consumed keys, so the canvas's bubble-phase Space handler never sees them.
Alternative
A window-capture listener alone, which would run after the keymap and could lose to a user hotkey bound to the same key.

Pointer blocking — items only

Context
The spec blocks pointer events on nodes, edges, and labels, and keeps panning empty canvas allowed.
Decision
LiveCanvas.isItemTarget() (nodes, edges, labels) decides what is blocked. A drag on empty canvas can still draw a selection box, but nothing selected can be moved, nudged, or deleted, because node pointer events and edit keys are swallowed.
Alternative
Block every pointer event on the canvas, which would also kill touch panning on the phone.

Commands file location

Context
The spec listed command registration in index.ts.
Decision
Registered there with checkCallback, finding the slides controller for the active FileView.
Alternative
A separate commands module, which would need access to the per-view controller map.

Live check — synthetic keys

Context
CLI eval can only send synthetic KeyboardEvents. Dispatching on window made the target the window itself, so the capture/bubble separation didn't apply.
Decision
Re-ran with events dispatched on document.body, matching real key presses. Space advanced the slide and did not start a pan. After exit, PageDown wasn't prevented and Space panned again.
Alternative
Trust the window-dispatched result, which falsely showed Space leaking.

Review cycle 1 — app-global key capture (high)

Context
The reviewer found the Scope and window listener consumed keys app-wide, including in the command palette and other panes.
Decision
Added a pure shouldHandleKey guard (with unit tests). Keys are handled only when no modal is open, focus isn't in a text field, and the target is inside the presenting canvas, or is the body while that view is the active leaf. Verified live: typing Space and p into an outside input was not captured.
Alternative
Keep app-global capture.

Review cycle 1 — popouts, selection box, propagation

Context
The window listeners didn't cover popout windows, a drag on empty canvas could leave a rubber-band selection, and stopPropagation differed from the spec.
Decision
Listeners register on root.win. A WeakSet records keys the main-window Scope already handled, so the window listener acts only for keys it never saw (popouts). Selection is cleared on every pointerup on the canvas. The listener now uses stopImmediatePropagation.
Alternative
Leave popouts unsupported.

Live no-write check — hash artifact

Context
A test canvas hash changed after a session. Tracing showed 0 requestSave calls during presenting. The change happened when the tab closed: Obsidian re-serializes the file in its own JSON formatting, and the test file had been written by Python with different whitespace.
Decision
Treated as a test-fixture artifact. Parsed content (keys, node order) was identical, and the presentation session itself caused 0 saves.
Alternative
Treat it as a plugin write.
