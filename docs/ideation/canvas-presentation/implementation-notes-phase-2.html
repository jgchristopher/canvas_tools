Implementation Notes — Phase 2

Canvas Presentation · 2026-10-25 · Slides menu

Name modal — optional duplicate message

Context
Generalizing promptPathName needed per-caller error copy, but slide names are allowed to repeat.
Decision
NameErrors.duplicate is optional and falls back to the empty message. Paths keep their exact copy.
Alternative
A required duplicate message that slides would fill with dead text.

Path picker — cancel vs choose

Context
Obsidian suggest modals call onClose before onChooseItem.
Decision
Cancel resolution is deferred one tick, so a real choice resolves first and a dismissal resolves to undefined.
Alternative
Resolve on close immediately, which would race and drop the choice.

In-app check — temporary canvas

Context
The feedback loop needed slide writes against a real canvas without touching John's files.
Decision
Copied Shepherd Factory Lifecycle to a temporary Canvas Tools Test.canvas, exercised the actions through CLI eval, and deleted it afterwards. The diff showed only canvasToolsSlides changed. The original's hash was unchanged.
Alternative
Exercise the actions on the real canvas.

In-app check — hidden window limits

Context
With the Obsidian window hidden, no animation frames run. A scripted viewport change doesn't update scale, so captured rects reflect the last rendered view, and rapid scripted edits coalesce in Obsidian's 250ms history debounce.
Decision
Verified the data writes, the go-to target (tx/ty/tZoom), path highlighting on edge elements (14/14 lit), and the missing-path fallback. The visual pan and zoom, capture at a real zoom, and per-action undo are left for John's hands-on pass.
Alternative
Ask John to bring the window forward mid-run.
